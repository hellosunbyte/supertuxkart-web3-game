# Browser build: local development

This is a port of the C++ game, not a JavaScript remake. Native Mac game
installation is unnecessary. Generated tools, libraries, media, and builds stay
inside ignored `build-web*` directories.

## First-time setup

Requirements: Python 3.10+, CMake, Ninja, Git, Perl, Make, and an Emscripten SDK.
On macOS, the command line developer tools provide Make and Perl. Install only
missing development tools; you do not need a native SuperTuxKart application.

From the repository root:

```sh
git clone https://github.com/emscripten-core/emsdk.git build-web-tools/emsdk
python3 build-web-tools/emsdk/emsdk.py install 4.0.10
python3 build-web-tools/emsdk/emsdk.py activate 4.0.10
```

`web/build.py` finds this SDK automatically. For another location, pass
`--sdk /absolute/path/to/emsdk`. Downloads require internet access.

## Prepare the media

Obtain an extracted SuperTuxKart asset set containing `karts`, `tracks`,
`textures`, `models`, `library`, `music`, and `sfx` (see [INSTALL.md](../INSTALL.md)).
The official [1.5-rc1 mobile LQ pack](https://github.com/supertuxkart/stk-assets-mobile/releases/tag/1.5-rc1)
is a smaller development option; it does not provide every current desktop asset.
Prefer assets matching your source revision when testing all content.

```sh
python3 web/prepare_assets.py /path/to/extracted-assets
```

This copies external media and overlays this revision's UI, XML, fonts, and
shaders into `build-web-tools/data`. It does not edit the original asset set.
The tool requires a fresh output directory to avoid stale files. If preparing
another pack, choose `--output build-web-tools/data-new` and use
`web/build.py --assets build-web-tools/data-new`.

The test pack used during this port is `1.5-rc1/stk-assets-lq.zip`, SHA-256:
`8cf5e0d5e2ab017745b9d5da6c4dc44aaf55e7d94e6c8f967b2afb584051f524`.

## Compile and run

```sh
python3 web/build.py
python3 web/serve.py
```

Open **http://localhost:8080** and click **Play**. The initial download is large
because this implementation preloads game data. Emscripten caches the asset pack
in IndexedDB for subsequent sessions and page loads, with version checks when the
pack changes. If browser storage is unavailable or full, it falls back to a
download. This asset cache is separate from player saves. Later builds reuse
compiled dependencies, so editing C++ usually only rebuilds affected files.

On first launch, keep **Offline Account** selected, choose a local player name,
and click the green **OK** button. Confirm your player on the Login screen,
then select Single Player. Use the page's
Fullscreen button for browser fullscreen.

The game frame has visible **Pause / Menu** and **Quit game** buttons, including
in fullscreen. Pause / Menu opens the native menu with **Exit Race** / **Exit
Battle**, restart, and resume actions. Quit game ends the entire session after
confirmation, even before a race or activity finishes. **Keep playing** or Escape
cancels the confirmation; a race that was already paused stays paused.

Quitting returns to this page and automatically exits fullscreen. After the final
save and session preparation, click **Play again**; no page reload is needed.

The build produces `build-web/web/index.html`, `game.html`, `supertuxkart.js`,
`supertuxkart.wasm`, `supertuxkart.data`, and worker files if generated by the SDK.
Keep the complete directory together. Double-clicking HTML via `file://` will not
work. The development server binds only to your computer.

Check its HTTP headers and WebAssembly delivery with:

```sh
python3 -m unittest discover -s web
```

To test real native quit/replay, automatic fullscreen exit, and saves between
sessions in Chrome (with the local server running):

```sh
npm install --prefix build-web-tools/browser-test playwright@1.58.2
node web/test_replay.mjs
node web/test_quit_during_play.mjs
node web/test_browser_startup.mjs
node web/test_full_race.mjs
```

The test uses Chrome installed on macOS. Elsewhere, install Playwright's Chromium
or set `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` to your browser executable.

### Full-race checks and measurements

`test_full_race.mjs` uses the game's native lap-based profiling mode: two AI karts
must complete actual laps, emit finish statistics, and exit through normal native
shutdown. It verifies final-save restoration and replay readiness without a page
reload, then checks a launcher reload: the asset pack must download only once
across all sessions and reloads. Profiling skips the human results screen; it does
not verify human driving,
progression/highscores, gamepad behavior, or audible sound.

For a longer content check:

```sh
RACE_TRACKS=olivermath,lighthouse RACE_LAPS=3 node web/test_full_race.mjs
```

Override `GAME_URL` to test another local port or a deployed build. Optionally set
`RACE_TIMEOUT_MS` (default 600000 per wait) for slower machines. Logs, screenshots,
and `report.json` are written under ignored
`build-web-tools/browser-test/full-race/`. The report includes browser/GPU identity,
asset response sizes and resource timings, startup time, sampled Wasm memory,
browser animation-frame intervals, and native kart finish times. Repeated asset
responses can come from cache: use resource `transferSize` when inspecting network
traffic, rather than adding up response `Content-Length` values.
The two documented color-emoji font diagnostics are recorded as known limitations;
other native error/fatal messages fail the full-race check.

Browser checks default to SwiftShader for reproducible functional coverage.
To request the machine's GPU in a visible Chrome window:

```sh
BROWSER_GPU=hardware BROWSER_HEADLESS=0 node web/test_full_race.mjs
```

Check the reported renderer before interpreting measurements as hardware results.
Frame intervals are browser scheduling samples, not a guaranteed game FPS; native
profile "Average FPS" counts simulation updates and is not a render-rate metric.
Localhost startup timings do not establish public-internet loading performance.

`test_browser_startup.mjs` checks unavailable browser features without downloading
the game, then verifies that actual missing JavaScript, Wasm, or data responses
produce terminal initialization errors and dispose of the failed runtime. It also
checks that an unavailable asset cache falls back to a download and reaches Play.

## Learn what changed

| Files | Purpose |
| --- | --- |
| `cmake/WebBrowser.cmake` | Separate WebAssembly dependency and linking rules; prevents linking native libraries. |
| `web/build.py` | Builds matching Emscripten ports, curl, OpenSSL crypto, then the game. |
| `src/main.cpp`, `src/main_loop.*` | Browser animation-frame scheduling and shared shutdown. |
| `lib/graphics_engine`, `lib/irrlicht`, graphics call sites | Excludes Vulkan APIs and selects the legacy GLES/WebGL path. |
| `src/audio/sfx_manager.cpp` | Processes bounded audio work on the browser thread. |
| `src/utils/browser_controls.cpp` | Bridges visible pause/quit controls to native pause and normal next-frame shutdown. |
| `web/pre.js` | Restores saves, serializes flushes, and provides a final save that quit can await. |
| `web/index.html` | Persistent launcher, Play again, fullscreen exit, and game log. |
| `web/game.html` | Isolated canvas/Wasm session; saves before the launcher replaces the terminated runtime. |
| `web/serve.py` | HTTP server with WebAssembly MIME type and isolation headers. |
| `web/test_full_race.mjs` | Native AI lap completion, save/replay checks, and measurement report. |
| `web/test_browser_startup.mjs` | Compatibility gating and initialization-failure regression checks. |

Imported compatibility work is credited in [UPSTREAM.md](UPSTREAM.md). Comments
explain browser-specific decisions at the code that implements them.

## Scope and deployment

This first target is offline single-player with keyboard/gamepad controls and
legacy graphics. Public servers, LAN multiplayer, add-on downloads, native
recording, and Web3 integration are outside this milestone. Native ENet/UDP does
not become browser networking merely by compiling to WebAssembly.

Settings/profiles are stored per browser and origin. Flushes run every five
seconds and are awaited on in-game quit. Closing the entire tab immediately after
a write may still lose the last few seconds.
Changing the hostname or port uses a different browser storage origin.

For deployment, upload **all** files from `build-web/web` to an HTTPS host. Set:

```text
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: require-corp
```

Serve `.wasm` as `application/wasm`. Localhost works over HTTP as a development
origin; deployed sites need HTTPS and the same isolation headers. A host that
cannot set those headers cannot serve this threaded build correctly.
